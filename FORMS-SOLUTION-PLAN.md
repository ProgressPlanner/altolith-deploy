# Forms Solution Plan for Static WordPress Sites

## The Problem

Static sites generated by Aether are **pure HTML/CSS/JS files** - no PHP backend to process:
- Comment forms (`wp-comments-post.php`)
- Search forms (query WordPress database)
- Contact forms (Contact Form 7, Gravity Forms, etc.)

## Available Resources

✅ **Static site** (HTML/CSS/JS on R2/CDN)
✅ **WordPress Playground instance** (already created per site, accessible via `/wp-admin/` redirect)
✅ **Cloudflare Free Services:**
  - Workers (100k requests/day)
  - D1 Database (5GB SQLite, 5M reads/day, 100k writes/day)
  - KV Storage (100k reads/day, 1k writes/day)
  - Turnstile (spam protection - unlimited free)
  - Email Workers (100 emails/day)

---

# Recommended Solution: **Hybrid Static + Playground Backend**

## Architecture Overview

```
Static Site (HTML/CSS/JS on R2)
    ↓ (form submission)
Cloudflare Worker (form-handler.workers.dev)
    ↓ (verify + process)
├─→ D1 Database (fast storage)
└─→ WordPress Playground (for WordPress compatibility)
    ↓ (on next publish)
Static Site Rebuild (includes new data)
```

## Why This Approach?

1. **Leverages Existing Infrastructure** - You already have Playground instances running
2. **WordPress Compatible** - Forms work exactly like in WordPress (`wp-comments-post.php`, plugins, etc.)
3. **Excellent UX** - Comments submitted immediately, search works offline
4. **Free Tier** - Well within Cloudflare limits
5. **Maintainable** - Minimal code changes to Aether

# Solution Details

## 1. Search Functionality (Client-Side, Works Offline)

### How it works:
- During static site generation, create `search-index.json` with all pages
- Inject JavaScript into search forms that queries this index
- Instant search results without server calls

### Implementation:
```javascript
// Generated during publish: search-index.json
[
  {
    "url": "/blog/post-1/",
    "title": "My First Post",
    "excerpt": "This is a summary...",
    "content": "Full text content for searching..."
  }
]

// Injected into HTML with search forms
<script>
async function performSearch(query) {
  const index = await fetch('/search-index.json').then(r => r.json());
  return index.filter(page =>
    page.title.toLowerCase().includes(query.toLowerCase()) ||
    page.content.toLowerCase().includes(query.toLowerCase())
  );
}
</script>
```

### Pros:
- ✅ Instant search (no server delay)
- ✅ Works offline after first load
- ✅ No API calls (saves Worker requests)
- ✅ Great UX

### Cons:
- ⚠️ Limited to simple text matching (no fuzzy search initially)
- ⚠️ Index size grows with content (but compresses well with gzip)

## 2. Comment Forms (Worker → D1 → Playground)

### How it works:
1. User submits comment on static site
2. JavaScript intercepts submission, adds Turnstile (spam protection)
3. Sends to Cloudflare Worker endpoint
4. Worker verifies Turnstile, stores in D1 database
5. Worker forwards to Playground's `wp-comments-post.php`
6. Next site rebuild pulls approved comments from D1

### Implementation:

**Step 1: Detect comment forms during static generation**
```javascript
// In htmlProcessor.js
if (html.includes('id="commentform"')) {
  // Inject Turnstile widget
  // Inject form submission JavaScript
  // Intercept submit, POST to Worker
}
```

**Step 2: Cloudflare Worker handles submission**
```javascript
// New Worker: FormHandlerWorker.js
async function handleComment(request, env) {
  const formData = await request.formData();

  // Verify Turnstile (spam protection)
  const isHuman = await verifyTurnstile(formData.get('cf-turnstile-response'));
  if (!isHuman) return error('Verification failed');

  // Store in D1 for fast retrieval
  await env.DB.prepare(`
    INSERT INTO comments (post_slug, author, email, content, status, created_at)
    VALUES (?, ?, ?, ?, 'pending', ?)
  `).bind(postSlug, author, email, content, new Date()).run();

  // Forward to Playground for WordPress processing
  await fetch(playgroundUrl + '/wp-comments-post.php', {
    method: 'POST',
    body: formData
  });

  return success('Comment submitted!');
}
```

**Step 3: Display on static site**
- Comments stored in D1 with status: `pending`, `approved`, `spam`
- Admin moderates via WordPress dashboard (Playground)
- Next publish includes approved comments in HTML

### Pros:
- ✅ True WordPress compatibility (Akismet works, plugins work)
- ✅ Spam protection (Turnstile + Akismet)
- ✅ Fast submission (D1 stores immediately)
- ✅ Familiar moderation UI (WordPress admin)

### Cons:
- ⚠️ Comments appear after next rebuild (acceptable for static sites)
- ⚠️ Requires Worker deployment

## 3. Contact Forms (Worker → Email)

### How it works:
1. User submits contact form
2. Worker verifies Turnstile
3. Stores in D1 + sends email to admin
4. Admin views in WordPress dashboard

### Implementation:
```javascript
async function handleContact(request, env) {
  const { name, email, message } = await request.json();

  // Verify Turnstile
  if (!await verifyTurnstile(token)) return error();

  // Store in D1
  await env.DB.prepare(`
    INSERT INTO contact_submissions (name, email, message, created_at)
    VALUES (?, ?, ?, ?)
  `).bind(name, email, message, new Date()).run();

  // Send email to admin (Email Workers - 100/day free)
  await sendEmail(env.ADMIN_EMAIL, {
    subject: 'New Contact Form',
    body: `From: ${name} (${email})\n\n${message}`
  });

  return success('Message sent!');
}
```

### Pros:
- ✅ Immediate notification (email)
- ✅ Stored for reference (D1)
- ✅ Simple implementation

### Cons:
- ⚠️ Limited to 100 emails/day (fine for most sites)

# Alternative Approaches

## Option B: Worker + D1 Only (Simpler, Less Compatible)

**Skip Playground, use D1 as primary storage:**
- Comments stored in D1 only
- Custom moderation UI (build in WordPress admin)
- No WordPress plugin compatibility

### Pros:
- ✅ Simpler (no Playground calls)
- ✅ Faster (one less hop)

### Cons:
- ❌ No Akismet or WordPress plugins
- ❌ Need custom moderation UI
- ❌ Less WordPress-like

---

## Option C: Email-Only (Simplest, Manual)

**All forms just send emails:**
- No database
- Admin processes manually
- Best for low-traffic sites

### Pros:
- ✅ Extremely simple
- ✅ No database needed

### Cons:
- ❌ Manual processing
- ❌ No automated workflows
- ❌ Limited to 100 emails/day

## D1 Database Schema

```sql
-- Comments table
CREATE TABLE comments (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    site_key TEXT NOT NULL,
    post_id INTEGER,
    post_slug TEXT NOT NULL,
    author TEXT NOT NULL,
    email TEXT NOT NULL,
    website TEXT,
    content TEXT NOT NULL,
    status TEXT DEFAULT 'pending',  -- pending, approved, spam
    parent_id INTEGER DEFAULT 0,
    created_at TEXT NOT NULL,
    approved_at TEXT,
    ip_address TEXT,
    user_agent TEXT
);

CREATE INDEX idx_site_post ON comments(site_key, post_slug);
CREATE INDEX idx_status ON comments(status);
CREATE INDEX idx_created ON comments(created_at);

-- Contact form submissions
CREATE TABLE contact_submissions (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    site_key TEXT NOT NULL,
    name TEXT NOT NULL,
    email TEXT NOT NULL,
    subject TEXT,
    message TEXT NOT NULL,
    created_at TEXT NOT NULL,
    ip_address TEXT,
    user_agent TEXT
);

CREATE INDEX idx_site_contact ON contact_submissions(site_key);
CREATE INDEX idx_created_contact ON contact_submissions(created_at);

-- Search queries (analytics)
CREATE TABLE search_queries (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    site_key TEXT NOT NULL,
    query TEXT NOT NULL,
    results_count INTEGER,
    created_at TEXT NOT NULL
);

CREATE INDEX idx_site_search ON search_queries(site_key);
```

## Integration Points

### 1. Static Site Generation
- **When:** During `generateStaticSite` step
- **What:**
  - Detect forms in HTML
  - Inject form handler JavaScript
  - Generate search index
  - Upload search index to R2

### 2. Form Submission
- **When:** User submits form on static site
- **What:**
  - JavaScript intercepts submit event
  - Validates form fields
  - Gets Turnstile token
  - POSTs to Cloudflare Worker
  - Displays success/error message

### 3. Worker Processing
- **When:** Receives POST from static site
- **What:**
  - Verifies Turnstile token
  - Stores in D1 database
  - Forwards to Playground (optional)
  - Sends email notification (optional)
  - Returns JSON response

### 4. Admin Moderation
- **When:** Admin opens WordPress dashboard
- **What:**
  - Fetches pending comments from D1
  - Displays in WordPress admin UI
  - Admin approves/rejects/marks as spam
  - Updates D1 status

### 5. Rebuild Integration
- **When:** Next publish/rebuild
- **What:**
  - Fetches approved comments from D1
  - Injects into HTML during generation
  - Comments appear on static site

5. ✅ **Scalable** - Handles thousands of submissions/day

**Start with Search (Phase 1)** - Quick win, immediate value, no external dependencies. Then add comments and contact forms progressively.
